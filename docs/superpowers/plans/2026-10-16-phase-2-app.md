# Phase 2 — Standalone macOS app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu-bar macOS app "Tape In" that advertises one receiver, plays every sender through the output device the user picks (with per-source fader, mute, solo and meter), can be renamed, and can start at login.

**Architecture:** The Phase-1 core gains the audio-side pipeline described in ARCHITECTURE.md §2: a transport-neutral `SpscRing` per session (network → audio), a `SourceStream` per session on the audio thread (libsamplerate resampler + buffer-level `DriftController` + gain/mute/solo + meter + underrun fades), a lock-free `Mixer`, and an `Engine` that owns the reactor thread, implements `IPcmSink`, keys sources by DACP-ID and exposes a control API for the UI. The JUCE app (`app/`) is a thin layer: `AudioDeviceManager` → `Mixer::render`, a window with one row per source, a status-bar icon, settings in a properties file, and an `ILoginItem` backed by `SMAppService`.

**Tech Stack:** C++20, CMake, JUCE 9.0.4 (AGPLv3), libsamplerate 0.2.2 (BSD-2), Mbed TLS, Apple ALAC, Catch2, dns_sd, SMAppService (Obj-C++).

**Spec:** `docs/SPEC.md` §1 (v1 scope), §6 Phase 2, §7; `docs/ARCHITECTURE.md` §0, §1 (threads, session model), §2 (data path), §4 (`ILoginItem`), §6, §11, §13 (Q6, Q7, Q12, Q13 defaults).

## Global Constraints

- C++20; `core/` and `platform/` never include JUCE; Objective-C++ only under `platform/macos/` and `app/`.
- Every source file starts with `// SPDX-License-Identifier: AGPL-3.0-or-later` and `// Copyright (C) 2026 Tape In contributors`.
- Naming: `snake_case` files in core/platform, `PascalCase` component files in app; types `PascalCase`, functions `camelCase`, constants `kPascalCase`, members `m_` in core only.
- Audio thread: zero locks, zero allocation, zero I/O, zero logging; atomics and SPSC rings only; underrun → fade to silence over a few ms.
- Network input stays hostile: nothing in this phase relaxes a Phase-1 check.
- Dependencies: JUCE 9.0.4 under AGPLv3, libsamplerate 0.2.2 BSD-2-Clause; both listed in `THIRD_PARTY.md`. No other new dependency.
- macOS deployment target 13.0; universal `arm64;x86_64`; bundle ID `app.tapein.mac`; product name "Tape In"; never "AirPlay" in product name or bundle ID; "Works with AirPlay. Not affiliated with Apple Inc." wherever AirPlay is mentioned in the UI.
- Default receiver name "Tape In" (Q7); session cap 100 (Q6); buffer mode default "sender sync", short modes are an advanced setting (Q12); "ignore sender volume" exists, off by default (Q13).
- Sanitizer and test gating on the `ctest` exit code. Whole suite (`ctest --test-dir build`) must be green after every task.
- Maintainer is addressed in Portuguese; everything in the repo in English.

## Review Focus

1. Audio callback with unusual shapes: 1 frame, 8192+ frames, 1 output channel, 8 output channels. The mixer must never write past the buffers or allocate; chunking covers large blocks. Test pinned in Task 6.
2. Output device switches sample rate mid-stream (44.1 → 96 kHz, or back): ratio jumps without garbage, no click beyond the switch itself, no crash. Test pinned in Task 5.
3. Sync packets whose sender latency is smaller than the hold-back window (target fill ≤ 0): the target is clamped to a sane minimum and playback still starts. Test pinned in Task 7.
4. Renaming to an empty, 200-character or non-ASCII name: the Bonjour instance stays ≤ 63 bytes of UTF-8, empty falls back to "Tape In". Test pinned in Task 7.
5. Engine stopped while sources are live and the audio callback is running: no use-after-free; sources are freed only after the audio thread has moved on. Test pinned in Task 6 (garbage collection) and Task 7 (stop with live sources).

namespace tapein::core::buffer {
struct SpscRingHeader {            // 64 bytes, offsets only; works over heap or a mapped region
    uint32_t magic;                // 0x52495054 "TPIR"
    uint32_t version;              // 1
    uint32_t sampleRate, channels, capacityFrames; // capacityFrames is a power of two
    std::atomic<uint32_t> writePos, readPos;       // frame counters, wrap mod 2^32
    std::atomic<uint32_t> discardRequest;          // producer sets; consumer clears
    std::atomic<uint32_t> heartbeat;               // producer increments per write
    uint32_t reserved[6];
};
class SpscRing {                   // non-owning view over a region
public:
    static size_t bytesRequired(uint32_t capacityFrames, uint32_t channels) noexcept;
    static Result<SpscRing> create(std::span<std::byte> region, uint32_t capacityFrames, uint32_t sampleRate, uint32_t channels);
    static Result<SpscRing> attach(std::span<std::byte> region);
    // producer
    uint32_t write(std::span<const int16_t> interleaved) noexcept;   // frames written; partial when full
    void requestDiscardAll() noexcept;
    // consumer
    uint32_t read(std::span<int16_t> interleaved) noexcept;          // frames read
    uint32_t discard(uint32_t frames) noexcept;                       // frames dropped
    bool takeDiscardRequest() noexcept;                               // true once per request; drops everything readable
    // either
    uint32_t availableToRead() const noexcept; uint32_t availableToWrite() const noexcept;
    uint32_t capacityFrames() const noexcept; uint32_t channels() const noexcept; uint32_t sampleRate() const noexcept;
};
class HeapRing {                   // owns the bytes, exposes a SpscRing
public:
    static Result<HeapRing> create(uint32_t capacityFrames, uint32_t sampleRate = 44100, uint32_t channels = 2);
    SpscRing& ring() noexcept;
};
}
```

namespace tapein::core::dsp {
enum class StreamState : uint8_t { buffering, playing, fadingOut, refilling, stopped };
struct SourceParams {                                  // written by other threads, read on the audio thread
    std::atomic<float> senderGain{1.0f};               // linear; from RTSP volume
    std::atomic<float> userGain{1.0f};                 // linear; from the fader
    std::atomic<bool> mute{false}, solo{false};
    std::atomic<bool> ignoreSenderGain{false};
    std::atomic<uint32_t> targetFillFrames{66150};     // ring frames to hold before/while playing
    std::atomic<bool> stopRequested{false};            // fade out then StreamState::stopped
};
struct SourceMeters {                                   // written on the audio thread
    std::atomic<float> peakL{0}, peakR{0}, rms{0};
    std::atomic<uint32_t> fillFrames{0};
    std::atomic<uint8_t> state{0};
    std::atomic<float> ratioDeviation{0};
    std::atomic<uint32_t> underruns{0};
};
class SourceStream {
public:
    static constexpr uint32_t kDefaultMaxBlock = 4096;
    static Result<std::unique_ptr<SourceStream>> create(buffer::HeapRing ring, ResamplerQuality q, uint32_t maxBlockFrames = kDefaultMaxBlock); // allocates everything
    buffer::SpscRing& ring() noexcept;                    // producer side (network thread)
    SourceParams& params() noexcept; const SourceMeters& meters() const noexcept;
    /// Audio thread. Adds this source into left/right (frames ≤ maxBlockFrames, caller chunks).
    /// soloGate = 0 when another source is soloed and this one is not, else 1.
    void render(float* left, float* right, uint32_t frames, double deviceSampleRate, float soloGate) noexcept;
};
}
```

Behaviour (ARCHITECTURE §2): start playing only when `fill ≥ target`; 5 ms fade-in; gain = senderGain(or 1)·userGain·(mute?0:1)·soloGate·fade, ramped linearly across each block; when `fill < 20 ms` while playing → `fadingOut` (5 ms) then `refilling` (silence, consume nothing) until `fill ≥ target/2` → playing with fade-in; `fill > target + 1 s` → `discard(fill − target)` with fade; `takeDiscardRequest()` → fade out then `buffering`; `stopRequested` → fade out then `stopped` (renders nothing afterwards); meters: block peak per channel, RMS of the mix, post-gain; `ratioDeviation` from the controller.
